- **What changed in this phase:** I ran a careful code review over all of Plan A. It found 10 possible
  problems. I fixed 6, and left 4 alone on purpose (reasons in §5 below). The fixes:
  1. The reward pop-up could show **"Starts Thu, Sep 10" twice** for an NFL "get N picks right" reward
     that hasn't started yet. It now shows once.
  2. The **NFL Pick 'Em page banner** still showed the old wording. It now uses the same new sentence
     as the venue card.
  3. The **Partner Dashboard reward rows** had stopped saying how many prizes you give per week. They

     the app reads, and the card would say "check the schedule". The app now skips games that ended
     more than a day ago. This also makes the Create Reward screen read only that venue's games instead
     of the newest 200 across the whole platform, so it's cheaper.
  5. The Create Reward preview could disagree with guests for a few evening hours about whether an NFL
     reward "starts soon". It now uses the same Eastern-time date the server uses.
  6. A custom prize with a plural name ("Chicken Wings") read "a Chicken Wings". It now reads
     "20% off Chicken Wings".

### 5. Review findings, traps and facts

Review: `/code-review high` over the whole uncommitted Plan A diff. 10 findings:

| # | Finding | Outcome |
|---|---|---|
| 1 | Pop-up duplicate "Starts …" for NFL threshold upcoming | **Fixed** |
| 2 | `listVenueLiveShowdownSchedules` newest-200 truncation | **Fixed** (SQL filter) |
| 3 | Wizard/createReward read a different (platform-wide) schedule query than descriptions | **Fixed** (both use the venue read) |
| 4 | Dashboard row lost "N per period" | **Fixed** |
| 5 | Coupon `winDescription` uses the campaign's *current* terms (edit 500 → 1,000 pts and old coupons say 1,000) | **Declined.** Would need a terms snapshot on the win/redemption row (schema change). Only reachable via the admin edit path on a definition-based reward after someone has won. Raise with Andrew if he wants it; it pairs naturally with Plan B's coupon work. |
| 6 | `createReward` freezes date-specific text into `rules` | **Declined.** Phase 2 decision 7 (intentional fallback snapshot). Every current reader of a definition-based reward prefers `description`; the admin edit form re-saving `rules` is harmless because the composer ignores `rules` for definition-based rewards. |
| 7 | NFL Pick 'Em banner showed raw `rules` | **Fixed** (client-side Line 1) |
| 8 | Wizard preview UTC-midnight vs server Eastern date | **Fixed** |
| 9 | `attachNFLRewardUpcomingState` has no production caller | **Declined (cleanup only).** Its 8 tests use a minimal campaign type; moving them onto `attachRewardDescriptions` means full `ChallengeCampaign` fixtures. Harmless; its doc comment warns not to call it beside `attachRewardDescriptions`. Delete it in any future rewards cleanup. |
| 10 | Article for plural custom prizes | **Fixed** (heuristic; "Hummus" still reads "a Hummus") |

Traps / facts:
1. **PostgREST `.or()` with an ISO timestamp works unquoted.** Verified read-only against production
   on 2026-10-03: 6 `trivia_schedules` rows total, filter returned 5, exactly the 5 recurring rows
   expected. (Production is tiny: 6 schedules.)
2. Any test that mocks `@/lib/liveShowdownAdmin` for code that reaches `getVenueLiveTriviaSchedules`
   must now provide `listVenueLiveShowdownSchedules`, not `listAdminLiveShowdownSchedules`.
3. `lib/timezone.ts` is `server-only`; client components needing a zone date key use `Intl` directly.
4. The `verify` skill was **not** run: it needs seeded rows + auth cookies, and the only database is
   production (writes need Andrew's OK). So nothing has been seen rendered. The checklist covers it.
5. Don't run `tsc` and `next build` at the same time (`.next/types` is regenerated).
6. Exact composer output for every row (Chicago times, $50 gift card, "now" = 2026-10-03) was printed
   with a throwaway `tsx` script and copied into the checklist; regenerate the same way if wording
   changes (`TZ=UTC npx tsx --tsconfig tsconfig.json <script>` importing `@/lib/rewardDescription`
   and `@/lib/rewardGameSlots`; don't leave the script in the repo).
