### 3. Decisions made (don't re-ask)

- Andrew, 2026-11-15: merge PR #19 (done); push the 4a migration (done); **approve the map as drafted plus two Speed
  Music areas** — "Classical music" and "Instruments and music basics", era `Timeless` (Speed Music's era set is now
  `musicDecades` = the decades + `Timeless`); **run the Speed tagging now**; Live tagging waits for Phase 4c.
- Expiry date lives in **`speed_generation_metadata.expiresOn`** (string `YYYY-MM-DD`), indexed by an expression index,
  not in a new `trivia_questions` column. Reason: admission compares a hash of the whole row (`to_jsonb(prior)`), and
  the plan's 4b already puts `expiresOn` in the metadata; this keeps the guarded table's columns unchanged.
  **4b must write it with `expiresOnFor(era)`** (`"2026-03"` → `"2027-03-01"`).
- `expiresOn` = first day of the month 12 months after the event month. The monthly step retires rows with
  `expiresOn <= today`.
- Writing months (`writingMonths(today)`): newest = the month 7 days ago; a month is offered only while its questions
  would live 30+ more days (so nothing is written to expire next week). On 2026-11-15 that's 2026-01 … 2026-11.
- Tags may say "no area fits" (`area_id` null) during the one-time run only; the writer (4b) must use an active area
  (`validateTag(..., { requireActive: true, forWriting: true })`).
- The 30-day gap uses `written_at` (Speed: the row's `created_at`), never `tagged_at`.
- Slot choice: regular slots rotate through the non-Current-Events categories starting at a different one each UTC day;
  within a category cells sort by count, then least recently written, spreading across areas first; at least ⅓ of
  regular slots are 2000-present (swaps the lowest-priority older slots); Current Events spreads across areas and
  months. A category with no active areas still gets "category only" slots (area null).
- Visibility: `getHiddenSpeedCategories()` caches the flag 5 minutes per server instance and **fails closed** (hidden).
  It rides on `/api/trivia/quota` (already loaded by the picker) and filters `getTriviaQuestions` ("All Categories"
  excludes hidden categories; asking for a hidden one returns no questions).
- The old Gemini generator lists Current Events in `TOPICS` (so the Phase 0 contract test still holds) but never plans
  it (`DATED_CATEGORIES`).
- The housekeeping step was added to `trivia-nightly.yml` (after generation, `if: always()`), as the plan says. That
  workflow is still **disabled** (D2), so the visibility flag and expiry don't run until 4b re-enables it. Nothing
  needs them before 4b (no Current Events questions exist yet).
- Codex model: the strongest on the Pro plan is **`gpt-6-astra`** ("Frontier intelligence for the most demanding
  work", from `~/.codex/models_cache.json`, Codex CLI 0.163.0). Use it for the **writer** (4b). Tagging used
  **`gpt-6.1-sol`** ("latest workhorse") at medium effort: it's classification, quality was good in the trial, and it
  spends less plan usage.

  `question_variety_report(game, category)` (Variety page), `speed_trivia_refresh_category_visibility(category,
  threshold)`, `speed_trivia_expire_dated(today, apply, limit)`.

  `--game live` reads `data/live-trivia/categories/*.json` read-only (categoryName per file, first slug wins).
  Runs `codex exec --ignore-user-config --ephemeral --sandbox read-only` in an empty temp folder with an output
  schema. Stops on a lapsed login (exit code 2) or 3 failures in a row; re-running resumes (only untagged rows).

  `GATED_CATEGORIES` must match `minActiveToShow` in `lib/triviaCategories.ts` (tested).
- Admin: section id `trivia-variety` (Content group), `TriviaVarietySection` → `/api/admin/trivia/variety`
  (GET game+category; POST `add` / `toggle`). Current Events columns are months.
