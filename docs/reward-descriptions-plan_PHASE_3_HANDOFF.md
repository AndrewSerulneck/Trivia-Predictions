### 5. Facts and traps

1. **Wizard fixture shows "Check the Live Trivia schedule for the next game."** in the existing admin
   snapshot because its `gameSlots` is `[]`. That is the composer's intended "no matching game"
   wording, not a bug; with a slot (the new test) it names the time.
2. **Points-target preview and game-winner picker:** `useGamePicker` needs
   `NEXT_PUBLIC_REWARD_GAME_PICKER_ENABLED`; with it off, game-winner rewards use the period flow and
   the preview passes `gameWinnerSlots: null` (matches what `createReward` stores). Not exercised by a
   test with the flag on.
3. **NFL preview `upcomingStartDate`** = `nflSeason.fromWeekStartDate` when it is in the future (UTC
   midnight comparison). Server uses the season's first-week start for weekly scope; they can differ
   by a day around week boundaries — preview only.
4. **Responses not enriched** (Phase 2 §5.1): a just-created reward inserted from a POST response, or
   the NFL page banner (`/api/nfl-pickem/rewards`), has no `description` and falls back to `rules`
   (now the composer's frozen summary) / terms. Dashboard refetches after save, so it self-heals.
5. **`this week` in frozen `rules`** — see Phase 2 decision 7; readers should prefer `description`.
6. Don't run `tsc` and `next build` concurrently.
