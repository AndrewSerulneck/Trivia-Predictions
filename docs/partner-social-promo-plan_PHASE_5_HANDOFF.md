# Share to social: Phase 5 handoff (Instagram "Post now")

**For Andrew:** partners can now connect their Instagram once and post a Post, Story or Reel to it straight from
Share to social, with a link to the live post and a short "Recent posts" list. It is **built and tested, but
switched off and not live**. Nothing is committed, deployed or applied to the database. Before it can be tried,
four things need you (runbook `docs/partner-social-promo-meta-setup-runbook.md` §"Phase 5 setup"):

Preview. The encryption key `SOCIAL_TOKEN_KEY` is already in `.env.local` and Vercel Preview (generated by Claude,
never shown). Also: the Reel's sound is now 128 kbps instead of 160 (Meta's spec for posting through its API).
Cost: no cron, no new paid service; ≈1 status request per sheet open, ≤30 short checks per Reel posted.

### 5. Facts and traps
- Meta (docs read 2026-11-04): Instagram Login isn't offered to new apps; with Facebook Login the **Instagram account
  must be a professional account linked to a Facebook Page**; publishing uses the **Page token**; Stories via API are
  documented for business accounts; 50 published posts / 24 h per account (`content_publishing_limit`); containers
  expire after 24 h; JPEG only, ≤8 MB, feed ratio 4:5–1.91:1 (our Post is exactly 4:5); Reel MP4 must have the moov
  atom first (Mediabunny `fastStart: "in-memory"` ✓) and **no edit lists** (Mediabunny writes one only if a track's
  first timestamp isn't 0, unverified for our AAC track); audio AAC ≤48 kHz, 128 kbps.
- `.env.local`: a `cut -d= -f1 .env.local` name check was **declined** this session; don't read it in any form. The
  key was appended without checking for duplicates (it was new this phase).
- The Phase 4 callback test now mocks `@/lib/social/socialConnections` (the callbacks really delete now).
- Comments in source mention `SOCIAL_TOKEN_KEY` etc.; the contract test strips comments and looks for
  `process.env.<NAME>`. `pos_connections` also has `access_token_enc`; the rule excludes `lib/pos/`.
- Owner pages don't load the Supabase browser client; keep it that way (the upload is a plain `fetch`).
- `npm run build` was **not** run (it shares `.next` with Andrew's dev server on :3000).
